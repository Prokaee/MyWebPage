Aeriscalus

A multi-agent, retrieval-augmented (RAG) system for generating and validating grounded Gherkin .feature test scenarios for small unmanned aircraft (sUAS). Three coordinated views: system context, component architecture, and the agentic LangGraph workflow.

VIEW 1

System Context

The system boundary and the external actors and services it interacts with. A QA engineer drives Aeriscalus through the Web UI or the CLI; the engine calls a cloud LLM provider, grounds scenarios against real aviation-safety incidents, and emits validated .feature files for downstream drone simulators.

VIEW 2

Component / Container Architecture

The internal layering of the system, top to bottom along the request path: client → API → orchestration → tools → data. External services sit to the right of the layer that calls them. The badge on each layer marks the thesis contributor who built it. The two boxes at the bottom run offline and are not part of the interactive request path.

VIEW 3

Agentic Workflow — LangGraph state machine

The core contribution: a five-node state machine with two nested feedback loops. The inner loop (amber) regenerates until the Auto-Critic passes all seven dimensions or the iteration cap is hit; the outer loop (light) lets the human reviewer send the draft back for fresh retrieval. Node names and routing keys match src/graph/workflow.py and src/graph/routing.py.

1.15mean inner iterations
87.5%pass critique on first try
≈30.5 swall-clock / scenario
≈11 msMCP retrieval latency
7critic dimensions

Auto-Critic dimensions: Gherkin syntax · parameter plausibility · ISO 29119 compliance · retrieval grounding · incident traceability · completeness · scenario-coverage. All seven must pass for the draft to advance to the human gate.
